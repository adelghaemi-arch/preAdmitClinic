# بخش‌های عملیاتی آماده‌به‌کار

این سند **فهرست عملیاتی** قابلیت‌هایی است که در کد و UI نسخهٔ ۱ پیاده شده‌اند و برای استفادهٔ واقعی (با API زنده، نه فقط mock) آماده‌اند. جزئیات سناریو در یوزکیس‌هاست؛ اینجا برای اپراتور/مالک محصول «چه بخشی روشن است و از کجا باز می‌شود» نوشته شده است.

## ۰. مرز آمادگی

### داخل دامنهٔ آماده

ثبت هویت و قرارداد سازمانی، OTP، پیش‌پذیرش مشروط، مدارک/عکس/GPS، فهرست و پرونده پزشک، مانیتور ادمین/ناظر، پنل ادمین کل (ضدتقلب و خزانه)، کاتالوگ ایستگاه کلینیک (بدون صف)، قالب SMS، خروجی PDF پرسشنامه.

### خارج از دامنهٔ آماده (اسکلت UI یا future)

صف اتاق، پذیرش روز مراجعه، فراخوان پزشک، ویزیت صف‌محور، پاراکلینیک عملیاتی، همراه سلامتجو، زمان‌بندی سقفی قرارداد، ویترین news (فقط اسکلت دیپلوی).

فلگ محصول: `V1_PRODUCT_SURFACE = true` در `frontend/my/src/lib/workspace.ts` — صفحات و نقش‌های غیر-v1 از ناوبری حذف می‌شوند.

### نقاط ورود

| سطح | آدرس / مسیر |
|-----|-------------|
| فرانت کلینیک (my) | `https://my.nafasmed.ir` · لوکال Vite |
| API | `https://api.nafasmed.ir` · `/api/*` |
| ورود | OTP موبایل؛ ادمین کل seed: `09133752696` |
| دمو OTP | فقط وقتی `Auth__FixedOtp` ست باشد (غیر-prod) |
