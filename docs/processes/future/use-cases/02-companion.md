# یوزکیس‌های نقش همراه سلامتجو (`patient`)

نقش workspace برای پیگیری پرونده‌هایی با رابطه غیر از `self`. با `COMPANION_FEATURE_ENABLED = false` از سوییچر پنهان است؛ سناریوها برای طراحی محصول نوشته شده‌اند.

## فهرست

| شناسه | نام | اکشن فنی |
|-------|-----|----------|
| UC-CMP-01 | ورود و فعال‌سازی نقش همراه | OTP / سوییچ نقش |
| UC-CMP-02 | مشاهده فهرست سلامتجویان لینک‌شده | links + snapshot |
| UC-CMP-03 | پیگیری داشبورد پرونده مجاز | `GET_FULL_SNAPSHOT` |
| UC-CMP-04 | مشاهده وضعیت پرسشنامه | خواندن |
| UC-CMP-05 | مشاهده نقشه مسیر | خواندن |
| UC-CMP-06 | مشاهده گزارش مجاز | خواندن |
| UC-CMP-07 | اعلام حضور به‌جای سلامتجو | `PATIENT_STATION_CHECKIN` |
| UC-CMP-08 | خواندن اعلان‌ها | `MARK_ALERTS_READ` |
| UC-CMP-09 | به‌روزرسانی مختصات منزل | `UPDATE_PATIENT_HOME` |
| UC-CMP-10 | قطع لینک همراهی | `UNLINK_COMPANION` |
| UC-CMP-11 | مدیریت نشست‌های خود | `REVOKE_*` |

### UC-CMP-01 — ورود و فعال‌سازی نقش همراه

- **بازیگر اصلی:** همراه سلامتجو
- **بازیگر ثانویه:** سیستم
- **هدف:** کار کردن در نقش `patient` روی پرونده‌های غیرخود
- **پیش‌شرط:** حساب با حداقل یک لینک غیر-self؛ `COMPANION_FEATURE_ENABLED`
- **پس‌شرط موفقیت:** نقش فعال workspace برابر `patient`
- **اکشن فنی:** ورود/سوییچ نقش (`setRequestRole`)

#### سناریوی اصلی (موفقیت)
1. همراه وارد سیستم می‌شود (یا در دمو سوییچ نقش را باز می‌کند).
2. سیستم نقش «همراه سلامتجو» را در فهرست نقش‌های مجاز نشان می‌دهد.
3. همراه نقش همراه را انتخاب می‌کند.
4. سیستم ناوبری همراه (داشبورد پیگیری، لینک‌ها، نقشه/گزارش محدود) را بارگذاری می‌کند.

#### سناریوهای استثنا
- **2x.** feature خاموش است؛ نقش در سوییچر نیست و ادامه ممکن نیست.

### UC-CMP-02 — مشاهده فهرست سلامتجویان لینک‌شده

- **بازیگر اصلی:** همراه
- **بازیگر ثانویه:** سیستم
- **هدف:** دیدن پرونده‌هایی که به حساب او لینک شده‌اند
- **پیش‌شرط:** نقش `patient`؛ لینک‌های غیر-self
- **پس‌شرط موفقیت:** فهرست نسبت/اجازه نمایش داده شده است
- **اکشن فنی:** خواندن `CompanionLink`

#### سناریوی اصلی (موفقیت)
1. همراه صفحه «سلامتجویان همراهی‌شده» را باز می‌کند.
2. سیستم لینک‌های غیر-self را با نسبت و سطح اجازه فهرست می‌کند.
3. همراه یک پرونده را برای پیگیری انتخاب می‌کند.
4. سیستم همان پرونده را به‌عنوان زمینه فعال صفحات بعدی قرار می‌دهد.

#### سناریوهای استثنا
- **2x.** هیچ لینکی نیست؛ سیستم حالت خالی را نشان می‌دهد.

### UC-CMP-03 — پیگیری داشبورد پرونده مجاز

- **بازیگر اصلی:** همراه
- **بازیگر ثانویه:** سیستم
- **هدف:** دیدن وضعیت امروز سلامتجو در محدوده visibility
- **پیش‌شرط:** لینک فعال به `patientId`؛ نقش `patient` (نه owner روی همان لینک)
- **پس‌شرط موفقیت:** داشبورد پیگیری با داده‌های مجاز نمایش داده شده است
- **اکشن فنی:** `GET_FULL_SNAPSHOT`

#### سناریوی اصلی (موفقیت)
1. همراه پس از انتخاب پرونده، «پیگیری امروز» را باز می‌کند.
2. سیستم بررسی می‌کند لینک وجود دارد و رابطه self نیست.
3. سیستم وضعیت ایستگاه‌ها و اعلان‌های مجاز را نشان می‌دهد.
4. همراه تصمیم می‌گیرد به نقشه، گزارش یا اعلام حضور (در صورت manage) برود.

#### سناریوهای استثنا
- **2x.** لینک حذف شده؛ سیستم دسترسی را رد می‌کند.
- **2y.** کاربر به‌اشتباه نقش owner را روی پرونده غیرخود گذاشته؛ سیستم راهنمایی می‌کند نقش همراه را فعال کند.

### UC-CMP-04 — مشاهده وضعیت پرسشنامه

- **بازیگر اصلی:** همراه
- **بازیگر ثانویه:** سیستم
- **هدف:** فهمیدن اینکه پیش‌پذیرش سلامتجو تکمیل شده یا نه (بدون ارسال فرم)
- **پیش‌شرط:** لینک؛ در صورت نیاز فلگ visibility مرتبط
- **پس‌شرط موفقیت:** وضعیت draft/submitted یا تکمیل‌بودن intake دیده شده است
- **اکشن فنی:** خواندن

#### سناریوی اصلی (موفقیت)
1. همراه صفحه وضعیت پرسشنامه را باز می‌کند.
2. سیستم فقط وضعیت/خلاصه مجاز را نشان می‌دهد و کنترل‌های ارسال را برای همراه غیرفعال می‌کند.
3. همراه می‌فهمد آیا سلامتجو باید خودش فرم را تمام کند.

#### سناریوهای استثنا
- **2x.** همراه تلاش به ذخیره/ارسال فرم کند؛ سیستم رد می‌کند («فقط توسط خود سلامتجو»).

### UC-CMP-05 — مشاهده نقشه مسیر

- **بازیگر اصلی:** همراه
- **بازیگر ثانویه:** سیستم
- **هدف:** دیدن مسیر و مکان ایستگاه جاری سلامتجو
- **پیش‌شرط:** `visibility.journey` (یا معادل مجاز)؛ لینک فعال
- **پس‌شرط موفقیت:** نقشه/راهنمای مسیر نمایش داده شده است
- **اکشن فنی:** خواندن

#### سناریوی اصلی (موفقیت)
1. همراه «مسیر و مکان سلامتجو» را باز می‌کند.
2. سیستم در صورت مجاز بودن visibility، اتاق و وضعیت صف را نشان می‌دهد.
3. همراه از اطلاعات برای همراهی حضوری استفاده می‌کند.

#### سناریوهای استثنا
- **2x.** visibility journey خاموش است؛ سیستم بخش را پنهان یا پیام محدودیت می‌دهد.

- **پس‌شرط موفقیت:** گزارش فیلترشده نمایش داده شده است

#### سناریوهای جایگزین

### UC-CMP-07 — اعلام حضور به‌جای سلامتجو

- **بازیگر اصلی:** همراه
- **بازیگر ثانویه:** سیستم
- **هدف:** چک‌این ایستگاه وقتی سلامتجو خودش اپ را در دست ندارد
- **پیش‌شرط:** `permission = manage`؛ `intakeCompleted`؛ ایستگاه `waiting`
- **پس‌شرط موفقیت:** وضعیت `checked_in`
- **اکشن فنی:** `PATIENT_STATION_CHECKIN`

#### سناریوی اصلی (موفقیت)
1. همراه در داشبورد می‌بیند ایستگاه در انتظار حضور است.
2. همراه «اعلام حضور» را می‌زند.
3. سیستم permission=manage و وضعیت waiting و intake را چک می‌کند.
4. سیستم وضعیت را `checked_in` می‌کند و تأیید را نشان می‌دهد.

#### سناریوهای استثنا
- **3x.** permission فقط `follow` است؛ سیستم «دسترسی شما فقط پیگیری است» می‌دهد.
- **3y.** intake ناقص یا وضعیت ایستگاه نامعتبر؛ همان استثناهای UC-OWN-11.

### UC-CMP-08 — خواندن اعلان‌ها

- **بازیگر اصلی:** همراه
- **بازیگر ثانویه:** سیستم
- **هدف:** علامت‌خواندن اعلان‌های پرونده لینک‌شده
- **پیش‌شرط:** لینک به پرونده
- **پس‌شرط موفقیت:** اعلان‌ها `isRead = true`

#### سناریوی اصلی (موفقیت)
1. همراه اعلان‌های پرونده انتخاب‌شده را باز می‌کند.
2. همراه آن‌ها را می‌خواند و علامت می‌زند.
3. سیستم وضعیت خوانده‌شدن را ذخیره می‌کند.

### UC-CMP-09 — به‌روزرسانی مختصات منزل

- **بازیگر اصلی:** همراه
- **بازیگر ثانویه:** سیستم
- **هدف:** کمک به ثبت مبدأ مسیر برای سلامتجو
- **پیش‌شرط:** `permission = manage`
- **پس‌شرط موفقیت:** مختصات منزل پرونده به‌روز شده است

2. سیستم manage بودن لینک را تأیید می‌کند.
3. سیستم مختصات را ذخیره و مسیر را به‌روز می‌کند.

#### سناریوهای استثنا

### UC-CMP-10 — قطع لینک همراهی

- **بازیگر اصلی:** همراه یا سلامتجو
- **بازیگر ثانویه:** سیستم
- **هدف:** پایان دسترسی همراه به پرونده
- **پیش‌شرط:** feature روشن؛ نشست معتبر؛ لینک موجود
- **پس‌شرط موفقیت:** لینک حذف شده است
- **اکشن فنی:** `UNLINK_COMPANION`

#### سناریوی اصلی (موفقیت)
1. بازیگر از فهرست لینک‌ها گزینه قطع را می‌زند.
2. سیستم لینک را حذف می‌کند.
3. همراه دیگر آن پرونده را در فهرست نمی‌بیند.

#### سناریوهای استثنا
- **1x.** feature خاموش؛ 403.

### UC-CMP-11 — مدیریت نشست‌های خود

- **بازیگر اصلی:** همراه
- **بازیگر ثانویه:** سیستم
- **هدف:** قطع نشست جاری یا سایر دستگاه‌های خودش
- **پیش‌شرط:** نشست معتبر
- **پس‌شرط موفقیت:** نشست(های) هدف revoke شده‌اند
- **اکشن فنی:** `REVOKE_AUTH_SESSION`، `REVOKE_OTHER_AUTH_SESSIONS`

#### سناریوی اصلی (موفقیت)
1. همراه فهرست نشست‌ها را باز می‌کند.
2. همراه قطع نشست جاری یا سایر نشست‌ها را انتخاب می‌کند.
3. سیستم فقط نشست‌های همان `userId` را باطل می‌کند.
4. در صورت قطع نشست جاری، سیستم به ورود برمی‌گردد.
