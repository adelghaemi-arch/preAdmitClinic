# یوزکیس‌های ادمین کل (`platform`) — نسخهٔ ۱

در v1 ادمین کل همه لایه‌های سیستم را کنترل می‌کند و به شواهد GPS و عکس‌های ضدتقلب/پرونده دسترسی و بازبینی دارد. عملیات صف پذیرش/پاراکلینیک مربوط به فاز بعد است (در دمو فعلی ممکن است هنوز UI داشته باشند ولی در دامنه مستند v1 نیستند).

## فهرست

| شناسه | نام | اکشن فنی (دمو) |
|-------|-----|----------------|
| UC-PLT-01 | تغییر وضعیت کلینیک | `PLATFORM_UPDATE_CLINIC_STATUS` |
| UC-PLT-02 | تنظیمات پایه | `PLATFORM_UPDATE_SETTINGS` |
| UC-PLT-03 | پیکربندی/تست OSM | `PLATFORM_UPDATE_OSM_LOCAL`، `PLATFORM_APPLY_OSM_LOCAL_TEST` |
| UC-PLT-04 | مدیریت کاربران | `PLATFORM_UPSERT_USER` |
| UC-PLT-05 | فعال/غیرفعال کاربر | `PLATFORM_SET_USER_ACTIVE` |
| UC-PLT-06 | ریست دسترسی کاربر | `PLATFORM_RESET_USER_ACCESS` |
| UC-PLT-07 | بازبینی عکس و نشست ضدتقلب | `PLATFORM_REVIEW_FRAUD_SESSION` |
| UC-PLT-08 | بازبینی چندنشستی | `PLATFORM_REVIEW_MULTI_SESSION` |
| UC-PLT-09 | مشاهده GPS ثبت‌شده | خواندن شواهد + بازبینی مرتبط |
| UC-PLT-10 | قطع نشست‌های کاربر | `PLATFORM_REVOKE_USER_SESSIONS` / `REVOKE_AUTH_SESSION` |
| UC-PLT-11 | ثبت و مشاهده ممیزی | `PLATFORM_APPEND_AUDIT` |
| UC-PLT-12 | مشاهده سلامت فنی | خواندن UI |

---

### UC-PLT-01 — تغییر وضعیت کلینیک

- **بازیگر اصلی:** ادمین کل
- **بازیگر ثانویه:** سیستم
- **هدف:** کنترل وضعیت عملیاتی کلینیک در سطح پلتفرم
- **پیش‌شرط:** نقش platform
- **پس‌شرط موفقیت:** وضعیت به‌روز شده است
- **اکشن فنی:** `PLATFORM_UPDATE_CLINIC_STATUS`

#### سناریوی اصلی (موفقیت)
1. ادمین وضعیت را تغییر و ذخیره می‌کند.
2. سیستم وضعیت جدید را اعمال می‌کند.

### UC-PLT-04 — مدیریت کاربران

- **بازیگر اصلی:** ادمین کل
- **بازیگر ثانویه:** سیستم
- **هدف:** ایجاد/ویرایش کاربران رجیستری (همه نقش‌ها شامل ادمین کل)
- **پیش‌شرط:** نقش platform
- **پس‌شرط موفقیت:** کاربر upsert شده است
- **اکشن فنی:** `PLATFORM_UPSERT_USER` / `POST api/users`

#### سناریوی اصلی (موفقیت)
1. ادمین مشخصات و نقش کاربر را وارد می‌کند (شامل نقش ادمین کل در صورت نیاز).
2. سیستم کاربر را ذخیره می‌کند؛ فهرست همه کاربران را می‌بیند.

#### سناریوهای استثنا
- **1x.** نقش نامعتبر؛ رد می‌شود.

### UC-PLT-07 — بازبینی عکس و نشست ضدتقلب

- **بازیگر اصلی:** ادمین کل
- **بازیگر ثانویه:** سیستم، سلامتجو
- **هدف:** دسترسی به عکس‌ها/فریم‌های پیش‌پذیرش و ثبت نتیجه بازبینی
- **پیش‌شرط:** شواهد ثبت‌شده توسط سلامتجو
- **پس‌شرط موفقیت:** نتیجه بازبینی ذخیره شده است
- **اکشن فنی:** `PLATFORM_REVIEW_FRAUD_SESSION`

#### سناریوی اصلی (موفقیت)
1. ادمین پنل ضدتقلب را باز می‌کند.
2. سیستم نشست‌ها و فریم/عکس‌ها را نشان می‌دهد.
3. ادمین بازبینی را ثبت می‌کند (تأیید/رد/نیاز به اقدام).
4. در صورت نیاز نشست کاربر را قطع می‌کند.

2. جزئیات را مرور و نتیجه را ثبت می‌کند.

### UC-PLT-09 — مشاهده GPS ثبت‌شده

- **بازیگر اصلی:** ادمین کل
- **بازیگر ثانویه:** سیستم
- **هدف:** دیدن مختصات GPS ثبت‌شده کنار پیش‌پذیرش
- **پیش‌شرط:** `RECORD_USER_GPS` قبلاً توسط سلامتجو انجام شده
- **پس‌شرط موفقیت:** مختصات در شواهد بازبینی قابل مشاهده است
- **اکشن فنی:** خواندن شواهد ضدتقلب

#### سناریوی اصلی (موفقیت)
1. ادمین در بازبینی نشست، بخش موقعیت را باز می‌کند.
2. سیستم نقطه GPS و زمان ثبت را نشان می‌دهد.
3. ادمین آن را در تصمیم بازبینی لحاظ می‌کند.

#### سناریوهای جایگزین
- **2a.** GPS ثبت نشده؛ سیستم خالی/هشدار نبود موقعیت نشان می‌دهد.

### UC-PLT-10 — قطع نشست‌های کاربر

- **بازیگر اصلی:** ادمین کل
- **بازیگر ثانویه:** سیستم، کاربر هدف
- **هدف:** باطل کردن نشست‌ها پس از رویداد امنیتی
- **پیش‌شرط:** کاربر یا نشست هدف مشخص
- **پس‌شرط موفقیت:** نشست(ها) revoke شده‌اند
- **اکشن فنی:** `PLATFORM_REVOKE_USER_SESSIONS`، `REVOKE_AUTH_SESSION`

#### سناریوی اصلی (موفقیت)
1. ادمین قطع همه نشست‌ها یا یک نشست را انتخاب می‌کند.
2. سیستم نشست‌ها را باطل می‌کند.
3. کاربر باید دوباره وارد شود.
