# نفس

پیش‌پذیرش، جریان کلینیک و همراهی سلامتجو روی معماری modular monolith: فرانت React + API ماژولار Nabz و پایگاه‌داده SQL Server.

دادهٔ دامنه در دیتابیس و فایل‌های آپلود روی سرور (`server/persist/uploads`) ماندگار می‌شوند. `localStorage` فقط برای توکن نشست و نقش UI است.

---

## قابلیت‌ها

| حوزه | خلاصه |
|------|--------|
| **پیش‌پذیرش** | پرسشنامه ساختاریافته، آپلود مدارک، ثبت عکس و GPS |
| **جریان کلینیک** | پذیرش، صف‌ها، اتاق‌ها، اعلان‌ها و مسیر درمان |
| **پرونده الکترونیک** | ویزیت، تشخیص، پاراکلینیک و گزارش قابل چاپ |
| **همراه سلامتجو** | دسترسی محدود، نقشه مسیر و پیگیری وضعیت |
| **قرارداد سازمانی** | پکیج‌ها، سقف نوبت، قیف پیش‌ثبت‌نام و پنل ناظر |
| **ادمین کل** | کاربران، نشست‌ها، ضدتقلب، سلامت فنی و ممیزی |

### انتشار روی سرور

مرجع واحد (ویندوز):

```bat
server\publish.bat
```

ترتیب داخلی: config → اسکلت → بیلد کامل → rsync اختیاری (`DEPLOY_REMOTE` در `sync.config.bat`).  
سپس روی لینوکس در هر پوشهٔ `api` / `my` / `news`: `sudo docker compose up -d --build`.  
جزئیات: [`docs/shared/server-deploy.md`](docs/shared/server-deploy.md).

### بک‌اند (v1)

پیش‌نیاز: .NET 10 و SQL Server لوکال با دیتابیس `NabzClinic`.

```bash
cd backend
dotnet run --project src/Nabz.Api
```

Connection string در `backend/src/Nabz.Api/appsettings.Development.json` (پیش‌فرض `Server=localhost;Database=NabzClinic;...`). استارت API با `MigrateAsync` اسکیما را اعمال و seed اولیه را می‌زند.

## شروع سریع

پیش‌نیاز: Node.js ۱۸ یا بالاتر.

```bash
cd frontend
npm install
npm run dev
```

API را جداگانه بالا بیاورید (`dotnet run` در بخش بک‌اند)، سپس [http://localhost:5173](http://localhost:5173) را باز کنید. مسیر `/` بدون نشست معتبر به `/login` هدایت می‌شود.

| دستور | توضیح |

| `npm run dev` | سرور توسعه |
| `npm run build` | بیلد تولید |
| `npm run preview` | پیش‌نمایش بیلد |
| `npm run typecheck` | بررسی TypeScript |

## ورود (OTP پنج‌رقمی)

1. به `/login` بروید.
2. یکی از شماره‌های «ورود سریع» را انتخاب کنید، یا شمارهٔ معتبر وارد کنید.
3. در dev اگر `Auth__FixedOtp` ست باشد همان کد ثابت در UI نشان داده می‌شود و SMS ارسال نمی‌شود؛ در production کد از کاوه‌نگار (`Kavenegar__OtpTemplate`) پیامک می‌شود.
4. همان کد را وارد کنید — **به‌جز ادمین کل:** وقتی FixedOtp فعال است باید **کد نمایش‌داده‌شده + ۱** را بزنید (مثلاً نمایش `12345` → ورود `12346`).

نمونه‌ها (پس از seed API؛ قرارداد پایه `DEMO-ORG`):

| نقش | شماره | کد ملی | نکته FixedOtp |
|-----|--------|--------|----------------|
| ادمین کل | `09133752696` | — | ورود با پایه + ۱ |
| ادمین کلینیک | `09120000001` | — | همان پایه |
| پزشک | `09120000002` | — | همان پایه |
| سلامتجو (مریم‌السادات تابش) | `09123458910` | `0012345679` | همان پایه |
| ناظر سازمانی | `09123409876` | — | همان پایه |
| عضو آمادهٔ admit | `09121112233` | `0011223340` | همان پایه |
| تست بلاک پذیرش (خارج قرارداد) | — | `0099887766` | — |

## نکات عملیاتی

- بازنشانی محیط دمو از ریست فکتوری پلتفرم (غیر-production، با OTP) یا re-seed سرور انجام می‌شود؛ نه از پاک کردن `localStorage`.
- پنل ادمین کل تک‌مستأجر است و رجیستری چندکلینیک ندارد.
- هنگام روشن بودن دوربین پیش‌پذیرش، فریم امنیتی و GPS برای بازبینی ضدتقلب ثبت می‌شود.
- اسناد خام پرسشنامه و کدینگ در `docs/` و اسکریپت‌های تولید در `scripts/` قرار دارند.
