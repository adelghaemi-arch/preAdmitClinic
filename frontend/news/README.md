# news — ویترین عمومی و اتاق خبر «نفس»

یک سایت چندصفحه‌ای **بدون بیلد** برای سه مخاطب:

| مخاطب | سؤالش | جای پاسخ |
|-------|--------|----------|
| بیمارستان / کلینیک | «این با HIS چه فرقی دارد؟ چقدر وقت و پول می‌برد؟» | `hospitals.html` |
| بیمار / سلامت‌جو | «این سیستم چیست؟ سر من کلاه نمی‌رود؟ داده‌ام کجا می‌رود؟» | `patients.html` |
| شریک / سرمایه‌گذار | «سهم من چطور حساب می‌شود؟ چرا به عدد شما اعتماد کنم؟» | `partners.html` |

صفحه‌ها: `index`، `hospitals`، `patients`، `partners`، `news`، `article`، `voices`، `about`، `contact`.

## اجرا (پیش‌نمایش)

```bash
cd frontend/news
node serve.mjs            # → http://localhost:4321
# یا با هر سرور ایستای دیگر: python3 -m http.server 4321
```

> فایل‌ها را با دوبار کلیک (`file://`) باز نکنید؛ `content.json` با `fetch` خوانده می‌شود و مرورگر اجازهٔ آن را در `file://` نمی‌دهد.

## ویرایش محتوا

همهٔ متن‌ها، اعداد، خبرها، نظرات و پرسش‌ها در [`content.json`](content.json) هستند — بدون دست‌زدن به کد:

| کلید | چه چیزی |
|------|---------|
| `site` | نام برند، تلفن، ایمیل، آدرس، متن نوار بالایی، منو (`site.nav`) |
| `stats` | چهار عدد نوار آماری (برچسب «نمونه» را حذف نکنید تا ادعای اثبات‌نشده نماند) |
| `features` / `integrity` / `journey` | بلوک‌های صفحهٔ اصلی |
| `hospitalPains` / `integrationModels` / `roles` / `onboarding` / `pricing` | صفحهٔ بیمارستان و کلینیک |
| `partnerModels` / `wallRules` / `faq.partner` | صفحهٔ مشارکت و «دیوار شیشه‌ای» |
| `news` | خبرها: `id` (لینک مقاله)، `category`، `title`، `excerpt`، `body`، `image` (`reception` / `doctor` / `patient`) |
| `voices` | روایت‌ها؛ `tag` همان فیلتر صفحهٔ روایت‌هاست |
| `faq` | چهار دسته: `general`، `hospital`، `patient`، `partner` |
| `images` | نگاشت تصویر → مسیر و متن جانشین |

افزودن خبر: یک شیء تازه در `news` بگذارید؛ صفحهٔ فهرست، فیلترها (`category`)، جست‌وجو و صفحهٔ `article.html?id=…` خودکار به‌روز می‌شوند.

## ساختار فنی

```
frontend/news/
├── index.html … contact.html   # ۹ پوستهٔ سبک؛ محتوا با JS رندر می‌شود
├── app.js                      # رندر صفحه‌ها + آیکون‌های SVG + تعامل‌ها
├── content.json                # تنها منبع محتوا (فارسی، اعداد فارسی)
├── styles.css                  # توکن‌ها، کامپوننت‌ها، RTL و ریسپانسیو
├── serve.mjs                   # سرور پیش‌نمایش بدون وابستگی
└── assets/
    ├── fonts/                  # Vazirmatn (بدنه) + Lalezar (تیتر برند) — محلی، بدون CDN
    ├── img/                    # سه تصویر ادیتوریال نمونه
    └── favicon.svg
```

- **بدون وابستگی و بدون بیلد:** بازکردن پوشه روی هر هاست ایستا کافی است (همان الگوی `server/news`).
- **فونت محلی:** پیش‌نمایش بدون اینترنت هم درست دیده می‌شود؛ در دیپلوی می‌توانید به CDN سوییچ کنید.
- **تعامل‌ها:** سوییچ مخاطب در هیرو، فیلتر و جست‌وجوی خبر، فیلتر روایت‌ها، تب‌های پرسش متداول، فرم‌های نمونه، ماشین‌حساب سهم شریک.
- **فرم‌ها فعلاً فقط نمایشی‌اند** (`data-form`) و چیزی ارسال نمی‌کنند؛ برای اتصال، در `initForms` نقطهٔ ارسال اضافه کنید.

## قواعد محتوایی (مهم)

1. **هر عددی که ادعاست، برچسب «نمونه» دارد.** اعداد پایلوت تا وقتی داده واقعی نداریم، نباید به‌عنوان نتیجه منتشر شوند.
2. **روایت‌ها نمونه‌اند** و در صفحه هم صریح نوشته شده؛ با گرفتن رضایت کتبی، متن و نام واقعی جایگزین شود.
3. **هیچ‌جا نمی‌گوییم جایگزین HIS یا پروندهٔ رسمی هستیم.** این مرز، هم در متن و هم در صفحهٔ بیماران حفظ شده.
4. **حریم خصوصی بیمار با زبان ساده** نوشته شده (چه چیزی، چرا، چه کسی می‌بیند) — همان جدول در صفحهٔ `patients` و در سند [پرسشنامه](../../docs/شرط-نمایش-و-مخاطب-پرسشنامه.md) باید هم‌خوان بماند.
5. مسیر و لحن «دیوار شیشه‌ای» نباید به وعدهٔ حقوقی تبدیل شود؛ تعهد عددی فقط در توافق‌نامه.

## مرحلهٔ بعد (اگر طرح تأیید شد)

- انتقال به `frontend/news` با Vite یا همان ایستای فعلی + دیپلوی روی `server/news` ([راهنما](../../docs/shared/server-deploy.md)).
- اتصال فرم دمو به یک endpoint واقعی (`POST /news/lead`) و ثبت در `persist/news-data`.
- تولید خودکار `content.json` از یک CMS سبک یا Markdown برای اتاق خبر.
- بازبینی حقوقی متن‌های حریم خصوصی و شرایط پایلوت پیش از انتشار عمومی.
